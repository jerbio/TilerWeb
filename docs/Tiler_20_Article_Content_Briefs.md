# Tiler: 20 SEO & Product-Led Article Briefs

Implementation guide for the web, content, SEO, and design teams.

## Content strategy

Treat these as **20 implementation-ready content briefs**, not just article ideas. The web team should be able to hand each brief directly to a writer and designer.

The articles should not all look like traditional blog posts. Some should behave like educational guides, some like workflow explainers, some like product-led interactive pages, and some like vertical landing pages. That variety can support both SEO and conversion.

---

# Recommended Sitewide Article Layout

Use one reusable article system, but allow different modules to appear depending on the article.

## Above the fold

**Breadcrumb**

`Resources / Planning / Article title`

**H1**

Clear, search-oriented headline.

**Subheadline**

One sentence that explains the problem in plain language.

**Proof / benefit strip**

Three short benefits, for example:

- Plan around real constraints
- See the impact before changing anything
- Turn tasks into actual time

**Primary visual**

Prefer an animated Tiler scenario, not a generic stock image.

**Primary CTA**

Contextual to the article, not “Get Started.”

Examples:

- `Find where this fits`
- `Replan my day`
- `Plan these stops`
- `Preview my schedule`

## Main article body

Use this general sequence:

1. Problem
2. Why current approaches break
3. Real-world example
4. Framework or method
5. How to do it manually
6. Where software helps
7. Tiler example
8. FAQ
9. Contextual CTA

Throughout the article, add one or two interactive demonstrations.

The reader should understand the problem **before** Tiler appears.

## Sticky desktop sidebar

Desktop articles can use a right sidebar containing:

**On this page**

- Problem
- Example
- How it works
- Tiler example
- FAQ

Underneath:

**Try this in Tiler**

A small task input:

> “Pick up groceries before 7 PM.”

Button:

`Find a time`

This is much stronger than a generic signup CTA.

# 1. Why Your To-Do List Doesn't Tell You When You'll Actually Get Things Done

## SEO target

**Primary keyword:** `to do list vs calendar`

**Secondary terms:**

- task list vs calendar
- schedule tasks
- time blocking tasks
- planning tasks into calendar
- why to do lists don't work

## Search intent

Educational / problem-aware.

The reader already uses a task manager but feels overwhelmed because their task list keeps growing.

## Core thesis

A task list represents **obligations**.

A calendar represents **capacity**.

The problem is that most tools leave the user responsible for translating one into the other.

Tiler's opportunity is to own that translation layer.

## Recommended H1

**Why Your To-Do List Doesn't Tell You When You'll Actually Get Things Done**

## Hero subheadline

> Tasks tell you what matters. Your calendar tells you what is possible. The hard part is connecting the two.

## Article structure

### H2: Your task list and calendar answer different questions

Explain:

**Task list:**

> What should I do?

**Calendar:**

> Where is my time already committed?

The missing question:

> When can this realistically happen?

### H2: Why task lists become overwhelming

Discuss:

- infinite-looking backlog
- no awareness of available hours
- no travel awareness
- no deadlines reflected spatially
- tasks compete against meetings
- tasks may take longer than expected

### H2: The hidden work of turning tasks into plans

Use a concrete example.

Tasks:

- Call insurance company
- Pick up prescription
- Finish presentation
- Workout

Calendar:

- meeting 10–11
- lunch 12–1
- client meeting 3–4
- dinner 6:30

Show that the person must mentally solve the schedule.

### H2: A better model: commitments and flexible work

Introduce Tiler's conceptual distinction:

**Blocks** = rigid commitments.  
**Tiles** = flexible work that can move.

Do not over-brand this section. Explain the conceptual model first.

### H2: What happens when something changes?

Show:

Client meeting moves.

The task list doesn't care.

The calendar changes.

But now all the user's assumptions about where the tasks fit are invalid.

### H2: What an intelligent planner should do

Introduce four capabilities:

- know available time
- understand deadlines
- understand duration
- adapt when constraints change

### H2: How Tiler approaches the problem

Product demo:

> “Finish investor update, 90 minutes, before Thursday.”

Tiler evaluates availability and proposes a time.

## Interactive module

Allow reader to type:

> “I need to do **\_\_** for **\_** minutes before **\_\_**.”

Button:

**Find where it fits**

## Visual

Before / after comparison:

**LEFT:** Checklist with 12 tasks.

**RIGHT:** Actual daily timeline showing three tasks fitted between commitments.

## CTA

**Turn a task into time**

# Contextual CTA Rules

Do not end every article with:

> Start using Tiler today.

| Article topic | CTA                              |
| ------------- | -------------------------------- |
| Running late  | **Replan the rest of my day**    |
| Deadline      | **Find time before my deadline** |
| Errands       | **Plan my stops**                |
| Contractor    | **Replan today's jobs**          |

| Task list     | **Turn this task into time**     |
| TileShare     | **Propose a commitment**         |
| Travel        | **Plan around my locations**     |

The transition should feel:

**Question → answer → experience**

rather than:

**Question → article → sales pitch**

# Overall Strategy

The **resource section should become another onboarding surface for Tiler**.

Someone arriving from search should not merely learn about planning. They should encounter a small, working version of the Tiler mental model directly inside the article:

1. Give Tiler a task, constraint, change, or destination.
2. Let Tiler reason about the day.
3. Show a proposed outcome.
4. Let the visitor preview the impact.
5. Convert the visitor into the full product experience.

The goal is for each article to move a reader from:

**“I have this planning problem.”**

to:

**“I understand why this problem is hard.”**

to:

**“I can see how Tiler approaches it differently.”**

to:

**“I want to try this with my own day.”**
